# REQ-020: event spec for review

> New checkout is 3 steps: shipping, payment, review. Track each step so we can see where people drop off. Must not break the checkout conversion KPI.

**Summary.** Track each step of the new 3-step checkout so drop-off per step is visible, without changing checkout_conversion.

## Events

| Event | Change | Fires when |
|---|---|---|
| `checkout_step_viewed` | new | Each time a checkout step renders, including going back to a step. |
| `checkout_started` | reuse | Unchanged: fires once when the shopper enters checkout, before step 1. |

**checkout_step_viewed**

| Property | Type | Required | Allowed values |
|---|---|---|---|
| `cart_id` | string | yes | any |
| `step` | string | yes | shipping, payment, review |
| `step_number` | integer | yes | 1, 2, 3 |

## KPIs to confirm before engineering starts

- [ ] **checkout_conversion** (owner: finance-analytics): Must keep checkout_started firing once per checkout, not once per step.

## Pipeline proof

- `stg_checkout_step_viewed`: 6 valid samples pass; 5/5 broken samples caught
- `stg_checkout_started`: 6 valid samples pass; 1/1 broken samples caught

**Privacy.** No personal data; shipping address fields are not captured.
