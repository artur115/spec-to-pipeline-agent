# REQ-003: event spec for review

> Wishlist v1: signed-in users can save a product to a wishlist and remove it. We need to know how many people use it and which products get saved.

**Summary.** Wishlist v1 has no matching event in the catalog, so this spec adds two new events: wishlist_item_added and wishlist_item_removed. Both are keyed on product_id (SKU), the same as product_viewed and product_added_to_cart, so saves can be joined to product data. Usage ('how many people') comes from distinct users firing wishlist_item_added. 'Which products' comes from counting by product_id and category, net of removals. Only new events are added and no existing event or property changes, so no existing KPI's numbers change. If the wishlist page later adds a 'move to cart' button, that would extend product_added_to_cart and affect add_to_cart_rate (see questions).

## Questions for the PM
- Can users add to cart directly from the wishlist page in v1? If so, product_added_to_cart needs a new optional source value 'wishlist'. That would affect add_to_cart_rate (owner: growth), because those adds have no preceding product_viewed on /p/*.
- Where can users tap save in v1: only the product page, or also search results and recommendation carousels? This fixes the allowed values for source.
- Should adoption be reported against signed-in users only (the eligible base), or against all users?

## Events

| Event | Change | Fires when |
|---|---|---|
| `wishlist_item_added` | new | Fires once when the server confirms a product was saved to the signed-in user's wishlist. Do not fire on the tap itself, on failure, or if the product was already in the wishlist. If a signed-out user taps save and is sent to sign in, fire only after the save completes after sign-in. |
| `wishlist_item_removed` | new | Fires once when the server confirms a product was removed from the signed-in user's wishlist. Do not fire on failure or if the product was not in the wishlist. Do not fire when an item leaves the wishlist automatically, for example because the product was discontinued. |

**wishlist_item_added**

| Property | Type | Required | Allowed values |
|---|---|---|---|
| `product_id` | string | yes | any |
| `category` | string | no | any |
| `source` | string | no | pdp, search, recommendation |

**wishlist_item_removed**

| Property | Type | Required | Allowed values |
|---|---|---|---|
| `product_id` | string | yes | any |
| `category` | string | no | any |
| `source` | string | no | pdp, wishlist_page |

## Pipeline proof

- `stg_wishlist_item_added`: 6 valid samples pass; 2/2 broken samples caught
- `stg_wishlist_item_removed`: 6 valid samples pass; 2/2 broken samples caught

**Privacy.** Do not put email, name, phone or address in event properties. Identify the user only through the existing pseudonymous analytics user id set by the SDK at sign-in. Product SKU and category are not personal data. If wishlists later support names, notes or sharing, do not send free-text names or notes, or recipient details, in these events.
