# REQ-007: event spec for review

> we're testing an exit-intent popup with the newsletter form. need to know how often it shows and how many sign up from it

**Summary.** Add one new event, newsletter_popup_shown, to count how often the exit-intent popup is displayed. Extend newsletter_signed_up with a new signup_location value, exit_intent_popup, so sign-ups from the popup can be counted. Popup sign-up rate is sign-ups with signup_location = exit_intent_popup divided by newsletter_popup_shown. No personal data is captured.

## Questions for the PM
- Is this an A/B test with a control group that never sees the popup, or does every eligible visitor get it? If there are variants, we should add a variant property to both events so you can compare sign-ups and the overall newsletter_signup_rate across groups.
- Do you also want to know when people close the popup without signing up? If so, we would add a newsletter_popup_dismissed event; without it, non-sign-ups only show up as 'shown but no sign-up'.
- Should the popup's sign-ups count toward the existing newsletter_signup_rate KPI, or be reported separately? The answer decides whether that KPI's definition changes.

## Events

| Event | Change | Fires when |
|---|---|---|
| `newsletter_popup_shown` | new | Fires once each time the exit-intent newsletter popup is actually rendered and visible to the user. It does not fire when the exit-intent trigger is suppressed by frequency capping, or when the user has already subscribed. |
| `newsletter_signed_up` | extend | Unchanged: fires on a successful newsletter sign-up confirmation. When the sign-up comes from the exit-intent popup form, send signup_location = exit_intent_popup. |

**newsletter_popup_shown**

| Property | Type | Required | Allowed values |
|---|---|---|---|
| `page_path` | string | yes | any |

**newsletter_signed_up**

| Property | Type | Required | Allowed values |
|---|---|---|---|
| `signup_location` | string | yes | footer, newsletter_page, exit_intent_popup |

## KPIs to confirm before engineering starts

- [ ] **newsletter_signup_rate** (owner: growth): The KPI counts newsletter_signed_up per session. Popup sign-ups will raise the numerator, but some may be people who would otherwise have signed up via the footer or the newsletter page. The KPI's pages list (footer, /newsletter) also doesn't include the popup, which appears on any page. Growth needs to decide whether exit_intent_popup sign-ups are included in the KPI or filtered out. Any query that filters on the enumerated signup_location values must be updated.

## Pipeline proof

- `stg_newsletter_popup_shown`: 6 valid samples pass; 1/1 broken samples caught
- `stg_newsletter_signed_up`: 6 valid samples pass; 2/2 broken samples caught

**Privacy.** Do not send the email address, or anything derived from it such as a hash, as an event property. The form posts the email directly to the email provider, and the analytics event records only that a sign-up happened and where. Send page_path as the path only, with the query string and fragment stripped, because URLs can carry emails or tokens (for example from email campaign links). Do not log the typed form value on failed submissions.
