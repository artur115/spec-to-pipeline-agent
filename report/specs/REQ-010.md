# REQ-010: event spec for review

> can the data team make the dashboard better? it's hard to read

**Summary.** REQ-010 asks the data team to make 'the dashboard' easier to read. It names no dashboard, user action, or question to answer, and it may be a reporting or visualization change rather than a tracking change. There isn't enough here to spec events, so this returns questions for the VP Marketing instead. No catalog events are added, extended, or reused.

## Questions for the PM
- Which dashboard do you mean (name or link), and which charts or numbers on it are hard to read? For example, are you looking at checkout_conversion, newsletter_signup_rate, add_to_cart_rate, or something else?
- What question are you trying to answer from it that you can't today? For example: where do newsletter sign-ups come from, or which channels drive orders? This tells us whether we need new tracking or only a clearer layout.
- Is the problem how it's presented (too many charts, unclear labels, wrong time range or grouping) or the data itself (a metric is missing, or you don't trust a number)? Only missing or untrusted data needs a tracking change.


**Privacy.** This spec adds no events or properties, so no personal data is collected. If follow-up work adds tracking, for example to attribute marketing channels, it must not capture email, name, phone, or address. Use opaque IDs and fixed enumerated values such as signup_location instead of free-text form fields. Strip query strings that may contain personal data from page_path and referrer.
