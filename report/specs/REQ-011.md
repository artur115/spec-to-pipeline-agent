# REQ-011: event spec for review

> We're selling digital gift cards ($25-$500). Need to see gift card sales separately from regular orders, but they still count as revenue.

**Summary.** Extend order_completed rather than adding a new purchase event. Gift card sales stay inside the existing revenue figure, and two new optional properties (gift_card_revenue, gift_card_count) let analysts report them separately. This also works for orders that mix gift cards with regular products. A new fulfillment_method value, 'digital', covers gift-card-only orders, which are neither shipped nor picked up. The field is required, so without a valid value these orders would fail validation or be mislabeled 'ship'. Regular revenue = revenue - gift_card_revenue. Gift card revenue = sum(gift_card_revenue). Gift card order count = orders where gift_card_count > 0.

## Questions for the PM
- When a customer later pays for a regular order with a gift card, does order_completed.revenue include the gift-card-paid amount? If so, the money is counted twice: once at gift card sale and again at redemption. Finance needs to decide which point counts as revenue, and we may need a separate gift_card_redeemed_amount property.
- Do gift card purchases go through the standard /checkout flow and fire checkout_started? If they use a separate flow, checkout_conversion will be inflated, because gift card orders would have no matching checkout_started.
- Can a single order contain both gift cards and physical products? This spec supports mixed orders: fulfillment_method stays ship or pickup and gift_card_revenue holds the gift card portion. Please confirm that matches how checkout works.

## Events

| Event | Change | Fires when |
|---|---|---|
| `order_completed` | extend | Unchanged: fires once when an order is successfully placed, including orders that contain only gift cards or a mix of gift cards and regular products. |

**order_completed**

| Property | Type | Required | Allowed values |
|---|---|---|---|
| `fulfillment_method` | string | yes | ship, pickup, digital |
| `gift_card_revenue` | number | no | any |
| `gift_card_count` | integer | no | any |

## KPIs to confirm before engineering starts

- [ ] **checkout_conversion** (owner: finance-analytics): Gift card orders add to the order_completed numerator. If gift card purchases skip checkout_started, the ratio is inflated. If they use the normal checkout, conversion changes with the gift card mix. Decide whether to include or exclude gift card orders, using fulfillment_method or gift_card_count.
- [ ] **store_pickup_adoption** (owner: retail-ops): Gift-card-only orders arrive with fulfillment_method = 'digital' and increase the total-orders denominator, which lowers pickup share. Decide whether the denominator should exclude 'digital' orders.
- [ ] **return_rate** (owner: ops-analytics): Gift-card-only orders join the completed-orders denominator but are probably not returnable through return_requested, so the return rate drops. Consider excluding fulfillment_method = 'digital' orders.

**Privacy.** Gift card flows usually collect recipient name, recipient email, sender name and a personal message. Do not send any of these in events. Do not send the gift card code, PIN or balance-lookup token either, since these work like payment credentials. Record only amounts (gift_card_revenue), counts (gift_card_count) and order_id. Analytics can join to the order system by order_id if more detail is needed. If amount-level breakdowns are needed later, use the face-value amount or a gift card SKU (e.g. the denomination), never a per-card identifier.
