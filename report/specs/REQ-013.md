# REQ-013: event spec for review

> Trail guides are getting embedded videos. Track plays and how far people watch (25/50/75/100).

**Summary.** Embedded videos on trail guides are a new action, so this spec adds two new events. No catalog event covers video. guide_scrolled measures page scroll depth and feeds trail_guide_engagement, so it is left untouched. Video progress should not be folded into it. guide_video_played fires on the first play of a video in a page view. guide_video_progressed fires once for each 25/50/75/100 milestone, reusing the same percent enum pattern as guide_scrolled. Both events carry guide_id so they join to guide_viewed, and video_id so guides with several videos can be told apart.

## Questions for the PM
- Which player will the videos use (YouTube, Vimeo, or self-hosted)? This decides how engineering hooks into play and progress events, and whether a privacy-enhanced embed is needed.
- Will any videos autoplay, even muted? The spec assumes plays are user-initiated only and that autoplay starts do not fire guide_video_played. Please confirm, or ask for an autoplay flag if autoplay is planned.
- If a viewer seeks past a milestone (for example, jumps straight to 80%), should the skipped 25/50/75 milestones count? The spec counts milestones by playhead position reached, including by seeking. Say so if you would rather count only continuously watched time.

## Events

| Event | Change | Fires when |
|---|---|---|
| `guide_video_played` | new | Fires when the user starts playback of an embedded video on a trail guide page (/guides/*), on the player's first 'play' event for that video in the current page view. Do not fire on resume after pause, on replays after the video ends, or on autoplay starts. Fire once per video per page view. |
| `guide_video_progressed` | new | Fires when the playhead of an embedded trail guide video first reaches 25%, 50%, 75% and 100% of its duration in the current page view. Each milestone fires at most once per video per page view. Fire 100 on the player's 'ended' event, or at 99% or more for players that stop short. If the user seeks past several milestones, fire each skipped milestone once, in ascending order (pending PM confirmation). Never fire without a preceding guide_video_played for the same video in the page view. |

**guide_video_played**

| Property | Type | Required | Allowed values |
|---|---|---|---|
| `guide_id` | string | yes | any |
| `video_id` | string | yes | any |
| `video_position` | integer | no | any |
| `video_duration_seconds` | integer | no | any |

**guide_video_progressed**

| Property | Type | Required | Allowed values |
|---|---|---|---|
| `guide_id` | string | yes | any |
| `video_id` | string | yes | any |
| `percent` | integer | yes | 25, 50, 75, 100 |
| `video_duration_seconds` | integer | no | any |

## KPIs to confirm before engineering starts

- [ ] **trail_guide_engagement** (owner: content): No expected change. This spec deliberately does not touch guide_viewed or guide_scrolled, so the KPI definition and inputs stay the same. It is flagged because it is the content team's guide KPI and the obvious shortcut, reusing guide_scrolled.percent for video progress, would inflate it. Separately, embedding videos may change page length and therefore scroll depth. That is a product effect, not a tracking one, but content should expect a possible shift when videos launch.

**Privacy.** Neither event carries personal data. Send only guide_id, video_id, position, duration and percent. Do not send the video title, the full embed URL or query strings (they can contain tokens or tracking params), or any user or account identifiers exposed by the player API. If YouTube is used, embed in privacy-enhanced mode (youtube-nocookie.com). If Vimeo is used, set dnt=1, so the third-party player does not set tracking cookies before consent. Respect the site's existing consent state before loading the player and before firing these events.
