# REQ-017: event spec for review

> Users can now switch the site language (English, Spanish, French). Log language changes.

**Summary.** REQ-017 asks to log when users switch the site language between English, Spanish and French. No catalog event covers this, so the spec adds one new event, language_changed. It fires once per user-initiated switch and records the previous language, the new language and the platform. No existing KPI reads this event, so no KPI numbers change because of this spec. The questions below cover whether to break out where the switcher was used, whether automatic locale detection should count, and whether localized URL paths could affect page-based KPIs.

## Questions for the PM
- Where can users switch language (e.g. header, footer, account settings, a first-visit prompt)? If you want to compare these, we will add a switcher_location property with a fixed list of values.
- Should automatic language selection (from browser or device locale on first visit or open) also be logged, or only manual switches? This spec covers manual switches only.
- Does switching language change URL paths (e.g. /es/p/* instead of /p/*) or reload the page? If so, page_viewed paths may stop matching KPI page filters (add_to_cart_rate on /p/*, trail_guide_engagement on /guides/*, checkout pages) and page_viewed counts may rise. We should confirm with the KPI owners before launch.

## Events

| Event | Change | Fires when |
|---|---|---|
| `language_changed` | new | Fires once when the user picks a language different from the current one in the language switcher, and the new language has been applied. Does not fire if the user re-selects the current language. Does not fire for automatic locale detection. |

**language_changed**

| Property | Type | Required | Allowed values |
|---|---|---|---|
| `from_language` | string | yes | en, es, fr |
| `to_language` | string | yes | en, es, fr |
| `platform` | string | yes | web, ios, android |

## Pipeline proof

- `stg_language_changed`: 6 valid samples pass; 6/6 broken samples caught

**Privacy.** The event records only language codes and platform; it holds no personal data. Send fixed ISO 639-1 codes from the enum, not free-text locale strings or full browser Accept-Language headers, which can carry extra identifying detail. Do not attach email, name, phone or address. Rely on the existing anonymous or user ID already sent with every event. If a language preference is saved to the user's account, keep that in the product database, not in analytics properties.
